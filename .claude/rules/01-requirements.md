# Requirements & Product Thinking

Translate requests into actors, goals, flows, acceptance criteria and edge cases.

Before implementation consider:
- permissions;
- failure modes;
- mobile UX;
- data model;
- API;
- security;
- cost;
- observability;
- MVP scope.

Ask questions when the answer changes architecture, security, billing, data retention or public UX.

Propose better alternatives when a requested approach is likely to create avoidable complexity or risk, but let the product owner decide.

Do not invent requirements.
