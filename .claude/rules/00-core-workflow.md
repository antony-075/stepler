# Core Engineering Workflow

For non-trivial work: Explore → Plan → Clarify if needed → Implement → Test → Review → Document.

Never start by guessing repository structure, APIs, library behavior or infrastructure.

Before changing architecture, inspect existing code and docs.

Prefer small, coherent changes over broad rewrites.

If a requirement is materially ambiguous, ask. If low-risk, make the simplest reasonable assumption and state it.

Do not silently disagree with docs. Surface the conflict and update the ADR after agreement.
