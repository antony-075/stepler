## 1. Что исследовано

**Продуктовый контекст.** `docs/product/PRODUCT.md`, `mvp.md`, `user-stories.md`, `docs/architecture/discovery-questions.md`, `docs/ux/README.md`, `docs/ux/design-system.md`. Важные для дизайна факты из них:

- гость приходит по ссылке/QR без регистрации; путь «открыл → добавил → готово» — north star;
- права ссылки: `canUploadFiles`, `canSubmitText`, `canViewGallery`, `canDeleteOwn`; бывают view-only ссылки (галерея после события);
- режимы видимости: общая галерея или contribution-only (гость видит максимум свои файлы);
- лимиты MVP: фото и документы ≤ 50 MB, видео ≤ 2 GB (без ограничения длительности), до 100 файлов за раз, текст ≤ 5000 символов plain text, коллекция 10 GB, аккаунт 20 GB, 3 активных коллекции;
- форматы: JPEG, PNG, WebP, HEIC/HEIF, GIF; MP4, MOV, WebM; PDF, DOCX, XLSX, PPTX, TXT;
- имя гостя — необязательное поле «Як вас звати?», не становится публичным автоматически;
- нет pre-moderation; гость может пожаловаться на элемент; admin видит жалобы;
- ссылки: deactivate (обратимо), revoke (навсегда), rotate для default link (старый QR перестаёт работать);
- thumbnails и poster для видео создаются асинхронно — у элемента есть состояние «ещё обрабатывается»;
- на guest page обязательна короткая строка про Terms и Privacy без checkbox;
- admin в MVP не загружает контент.

**Скиллы.** Применены `frontend-design` (официальный), `ui-ux-pro-max`, `web-design-guidelines`, `responsive-design`, `shadcn` из `.claude/skills/`. Замечание по `ui-ux-pro-max --design-system`: на запрос «event photo collection memories consumer warm minimal» он предложил стиль «Organic Biophilic», зелёный `#15803D` и пару Fredoka + Nunito (детские/игровые продукты). Это не подходит Stepler, результат отброшен; из скилла взяты только правила приоритетов (контраст, 44px, reduced motion, mobile-first, CLS). Из `frontend-design` взят список типичных «шаблонных» признаков, которых каждое направление сознательно избегает: кремовый фон около `#F4F1EA` + контрастная serif-антиква + терракота около `#D97757`; почти чёрный фон с одним кислотным акцентом; газетная вёрстка с нулевым радиусом ради стиля; одинаковые rounded cards с одной тенью; ALL CAPS eyebrow над каждым заголовком; моноширинный шрифт для мелких подписей «для вида»; стрелка «→» в каждой кнопке.

**Референсы** (точки отсчёта, а не образцы для копирования):

| Референс | Что полезного | Что не берём |
| --- | --- | --- |
| Apple Photos, «Memories» | Заголовок прямо на фото, фото на весь экран, один момент — одна обложка | Автоматический монтаж, музыка, Ken Burns везде |
| Google Photos | Justified rows без обрезки, дата как структура, быстрый scrubber по времени | Плотность «всё подряд», отсутствие характера |
| Контактные листы (Magnum Contact Sheets, плёночная лаборатория) | Сетка кадров, номер кадра, пометки восковым карандашом как выбор | Буквальная «плёнка» с перфорацией как декор |
| Сайты плёночных лабораторий (Carmencita Film Lab, The Darkroom) | Конверт заказа как контейнер, статус «проявляется», красный/янтарный свет тёмной комнаты | Ретро-стилизация, шумные текстуры |
| Фотокниги (Artifact Uprising, Chatbooks) | Белые поля вокруг фото, разворот, спокойная бумага, мало шрифтов | Свадебная эстетика, рукописные шрифты |
| Editorial-журналы (Kinfolk, Apartamento) | Большое белое поле, подписи к фото, асимметрия, один шрифтовой голос | Нечитаемо мелкий текст, светло-серый на белом |
| Are.na | Нейтральный «блок» для любого типа контента (картинка, текст, файл), отсутствие лайков | Подчеркнутая академическая сухость |
| Cosmos | Спокойная сетка, фото как главный контент, минимум chrome | Бесконечная лента и discovery |
| Glass | Фото без лайков и счётчиков, тёмная тема как родная, уважение к кадру | Ориентация на профессионалов |

Общий вывод из референсов: сильнее всего ощущение «это про воспоминания» дают не декор, а (1) **поля вокруг фото**, (2) **время и авторство как подпись** («Додала Марта, 21:10»), (3) **последовательность** (кадры, страницы, стопка) и (4) **сдержанный chrome**, который отступает перед контентом. Все четыре направления используют эти четыре рычага по-разному.

## 2. Объективные ограничения (общие для всех направлений)

Это не вкус, а требования. Любое направление, которое их нарушает, нужно чинить, а не обсуждать.

### 2.1 Язык и шрифты

- **Украинский — язык по умолчанию**, английский второй. Каждый шрифт обязан содержать кириллицу, включая `Ґґ Іі Її Єє`, а также `’`, `«»`, `—`, `№`.
- **Проверка выполнена по файлам, а не по описанию.** Скрипт скачал с Google Fonts woff2 (subsets `latin`, `cyrillic`, `cyrillic-ext`) и проверил cmap через fontTools. Лицензии — по `google-font-licenses.json` из `ui-ux-pro-max` (проверено 2026-08-13).

| Шрифт | Где предложен | Лицензия | Кириллица | Ґ І Ї Є | `ʼ` (U+02BC) | Оси |
| --- | --- | --- | --- | --- | --- | --- |
| Source Serif 4 | A | OFL | да | да | да | opsz 8–60, wght 200–900 |
| Inter | A | OFL | да | да | да | opsz 14–32, wght 100–900 |
| Commissioner | B | OFL | да | да | да | FLAR, VOLM, slnt, wght |
| Literata | B | OFL | да | да | да | opsz 7–72, wght 200–900 |
| Geologica | C | OFL | да | да | да | CRSV, SHRP, slnt, wght |
| Geist Mono | C | OFL | да | да | да | wght 100–900 |
| Sofia Sans | D | OFL | да | да | да | wght 1–1000 |
| Sofia Sans Extra Condensed | D | OFL | да | да | да | wght 1–1000 |

Отвергнуты по объективной причине: **Fraunces, Instrument Serif/Sans, Newsreader, Young Serif, DM Sans, Figtree, Space Grotesk, Bricolage Grotesque, Schibsted Grotesk, Host Grotesk, Funnel Display, Petrona** — нет кириллицы на Google Fonts. **Wix Madefor Text/Display** — нет U+02BC.

Попутная находка про текущий UI: **Manrope** (текущий шрифт интерфейса) **не содержит U+02BC** (`ʼ`, модифицирующий апостроф, который рекомендует украинская орфография). U+2019 (`’`) в нём есть. Решение для любого направления: в копирайте использовать один апостроф последовательно (рекомендую `’` U+2019 — он есть во всех шрифтах и его вводят клавиатуры), либо выбирать только шрифты с U+02BC. Это стоит записать в правила текстов.

Отвергнут по нетехнической причине: **Golos Text** (технически полный) — заказан для государственных сервисов России; для украиноязычного продукта это нежелательная ассоциация. Это суждение, не ограничение, — владелец может не согласиться.

- **Подключение:** все шрифты — через `next/font/google` (self-hosted при сборке, без запросов к Google в рантайме) с `subsets: ['latin', 'cyrillic', 'cyrillic-ext']`. Дополнительные оси (`opsz`, `FLAR`, `SHRP`, `CRSV`) подключаются через `axes` и увеличивают файл; бюджет — не больше двух семейств и не больше ~120 KB шрифтов на guest-странице.
- **Длинные украинские слова.** Украинский текст в среднем на 15–25% длиннее английского, слова длиннее: «Завантажити», «Фотографії», «Налаштування», «Конфіденційності», «Деактивувати», «Переглянути». Следствия: кнопки не фиксированной ширины; на 320px заголовок до ~10–11 символов в строке при 40px (проверять на «Налаштування доступу»); `text-wrap: balance` для заголовков; `overflow-wrap: anywhere` для пользовательских названий коллекций; `hyphens: auto` с `lang="uk"` — проверить поддержку в целевых браузерах до того, как на неё полагаться; не использовать letter-spacing > 0 для украинских заголовков (кириллица и так широкая).
- **Без ALL CAPS** для меток: в кириллице капс читается тяжело и выглядит шаблонно.

### 2.2 Доступность

- **Контраст WCAG 2.x AA:** текст 4.5:1, крупный текст (≥24px или ≥18.66px bold) 3:1, границы полей и focus ring 3:1 (1.4.11). Все палитры ниже посчитаны скриптом по формуле WCAG (sRGB relative luminance); цифры приведены в таблицах. Где цвет не проходит 4.5:1 как текст, это явно помечено как «только заливка».
- **Touch targets ≥ 44×44px**, между соседними целями ≥ 8px. На guest-странице основное действие ≥ 56px.
- **`prefers-reduced-motion`:** каждое движение в каждом направлении имеет статичную альтернативу (описана). Под reduced motion сохраняется смысл (статус, порядок), пропадает только движение.
- **Focus visible** на всём, клавиатура везде, семантические заголовки, `aria-live` для прогресса загрузки (polite, с агрегированием, а не на каждый процент).
- **Не только цветом:** статус загрузки, «новое», «выбрано», «ошибка» всегда дублируются иконкой или текстом.
- **Текст на фото** — только на scrim/градиенте с измеренным контрастом (белый на `black/55` поверх белого пикселя ≈ 4.7:1) или под фото, не поверх.

### 2.3 Сеть и устройства гостя

- Гость на мобильной сети, часто в помещении с плохим сигналом, с телефоном в одной руке. Загрузка может длиться минуты (видео до 2 GB). Поэтому во всех направлениях: прогресс по файлам и общий, состояние «в очереди / загружается / готово / ошибка / отменено», явный retry для упавших, частичный успех как нормальное состояние («27 з 30 додано, 3 не вдалося»), предупреждение перед закрытием вкладки во время загрузки.
- HEIC с iPhone не отображается в большинстве браузеров до создания thumbnail — UI должен иметь плейсхолдер «готується прев’ю» для любого типа.
- Основное действие в зоне большого пальца (нижняя треть экрана), safe-area insets для iOS.

### 2.4 Технический стек

React + Next.js + TypeScript, Tailwind CSS 4, shadcn/ui + Radix (поведение и доступность берём у них, внешний вид — свой), Storybook, Motion (`motion/react`), Light/Dark, i18n uk/en. Ни одно направление не требует новой UI-библиотеки. Направления различаются токенами, композицией, типографикой и несколькими собственными компонентами (перечислены в «Стиль компонентов»).

## 3. Общие решения, не зависящие от направления

Эти принципы одинаковы для A–D, чтобы сравнение было честным:

1. **Guest-side: одно главное действие на экране.** Первый экран отвечает на «что это» (название коллекции) и «что делать» (одна кнопка добавить). Всё остальное вторично и ниже.
2. **Admin-side: контент → важные действия → навигация.** Галерея коллекции — центр admin-а, а не таблица.
3. **Фото не обрезаются агрессивно в галерее** (justified rows или masonry с исходными пропорциями), обрезка допустима только в мелких thumbnails и обложках.
4. **Не-фото контент — равноправные «объекты»:** видео (poster + длительность), документ (тип + название + страницы, если известны), текст (сама цитата), а не серые иконки файлов.
5. **Admin area — без декоративной атмосферы.** Характер в admin-е выражается типографикой, формой и галереей, а не фоном.
6. **Тёмная тема — отдельный дизайн** с собственной логикой для каждого направления.
7. **Брейкпоинты** (Tailwind 4 + один дополнительный): `base` 320–639, `sm` 640, `md` 768, `lg` 1024, `xl` 1280, `2xl` 1536, `3xl` 1920 (ultrawide). Внутри `base` отдельно проверяются 320 (маленький телефон, iPhone SE 1-го поколения, старые Android) и 375–430 (основной телефон). Компоненты внутри страниц реагируют на ширину контейнера (container queries), страницы — на viewport.

## 4. Direction A — «Тиша»

### 1. Название

**«Тиша»** (Quiet). Минималистичный editorial.

### 2. Главная идея

Коллекция — это номер журнала о событии. Интерфейс почти бесцветный и почти беззвучный: большое поле, сильная типографическая иерархия, фото на всю ширину колонки, подписи как в журнале. Характер даёт не декор, а **контраст масштабов**: огромное название события serif-антиквой и маленькие точные подписи к каждому моменту.

### 3. Визуальный характер

Белое поле, тонкие линии только там, где они разделяют информацию, отсутствие карточек. Асимметричная сетка: текст слева узкой колонкой, фото справа широкой. Один spot-цвет (приглушённый зелёный) используется так же редко, как в журнале: ссылки, выбор, фокус.

### 4. Эмоция

Спокойствие, уважение к моменту, «взрослость». Ощущение, что твои фото положили в красивую книгу. Риск — холодность; тепло обеспечивают подписи с именами и временем и сама фотография.

### 6. Typography direction

- **Display / заголовки: Source Serif 4** (Adobe, Frank Grießhammer). Ось `opsz` до 60 даёт настоящий дисплейный рисунок на больших кеглях и текстовый на мелких — одна гарнитура закрывает и название события 56–96px, и цитату гостя 18px. Кириллица нарисована полноценно, не «латиница с приделанными буквами».
- **UI и текст: Inter** с `opsz`. Сознательно нейтральный: в A голос продукта — serif, а sans должен быть невидимым инструментом. Табличные цифры для счётчиков и размеров файлов. (Альтернатива, если Inter кажется слишком повсеместным: IBM Plex Sans — проверен, тот же уровень покрытия, но более «технический» характер.)
- **Шкала:** 13 / 15 / 17 (body) / 20 / 28 / 40 / 56 / 80. Body 17px/1.55 на guest-странице, 15px/1.5 в admin. Заголовки serif 400–500, без жирного: иерархия размером, а не весом.
- **Гостевые текстовые сообщения** отображаются Source Serif 4 20–24px — как цитата в журнале. Это главная «фишка» A для не-фото контента.

### 7. Shape language

- Радиусы: контролы 6px, фото 0–2px (журнальная печать), диалоги 12px. Фото не скругляются: скругление превращает фото в «карточку».
- Границы: hairline 1px только для разделения строк в списках и под шапкой. Никаких рамок вокруг групп.
- Тени: практически нет. Одна тень для всплывающих слоёв (меню, диалог): `0 12px 32px -12px rgb(27 28 26 / 0.18)`. В dark — без тени, вместо неё `surface` светлее фона + 1px border.

### 8. Как используются фотографии

- **Разрешено:** фото на всю ширину колонки; асимметричная пара «большое + маленькое»; justified rows в галерее; одна фотография-обложка коллекции на guest-странице (если появится обложка — см. вопрос 9.3); подписи под фото (имя, время, тип).
- **Запрещено:** rotation, overlap, коллаж, рамки. Всё строго по сетке.
- **Без фото:** пустая коллекция выглядит как обложка журнала — название крупно, дата, одна строка описания. Это работает и без контента, что важно для только что созданной коллекции.

### 9. Стиль компонентов

- Кнопки: primary — чернильная заливка, высота 48 (guest 56), радиус 6, текст 16/600 Inter. Secondary — текстовая с подчёркиванием или outline 1px `input`.
- Inputs: полная граница 1px `input` (3.57:1), а не только нижняя линия (её хуже видно как поле), радиус 6, 48px, label над полем.
- Tabs: текст с подчёркиванием 2px spot-зелёным под активным.
- Badges: текст + маленькая точка, без заливки.
- Upload: список файлов как оглавление журнала — номер, название, размер, статус справа, тонкая линия прогресса под строкой.
- Свои компоненты: `EditorialHeader` (название + метаданные), `CaptionedMedia` (фото + подпись), `QuoteTile` (текст гостя).

### 10. Navigation

- **Guest:** нет навигации. Шапка — только маленький wordmark и переключатель языка; галерея (если разрешена) ниже по скроллу, без табов.
- **Admin:** верхняя строка: wordmark слева, аккаунт справа. Внутри коллекции — горизонтальные текстовые табы: «Вміст», «Тексти», «Доступ», «Скарги», «Налаштування». На телефоне табы скроллятся горизонтально.

### 11. Guest-side

Первый экран: wordmark мелко, название события serif 40–56px, одна строка описания, затем большая кнопка «Додати фото і відео» и тихая текстовая ссылка «Написати повідомлення». Под ними — галерея (если `canViewGallery`) или строка «Ваші файли побачить лише організатор» (contribution-only). Внизу — строка про Terms/Privacy.

### 12. Admin-side

Список коллекций как оглавление: крупные названия serif, справа количество и статус. Внутри коллекции — сначала контент, плотная justified-галерея; действия (поделиться, QR) в шапке коллекции.

### 13. Motion

- Появление фото: crossfade 200ms от плейсхолдера доминирующего цвета (цвет считается worker-ом вместе с thumbnail — вопрос к архитектуре, иначе нейтральный плейсхолдер).
- Upload: линия прогресса растёт линейно; по завершении строка коротко подсвечивается жёлтым и гаснет (400ms).
- Новый контент в галерее admin-а: вставка без сдвига (место резервируется), fade 150ms.
- Создание коллекции: заголовок «набирается» мгновенно, без анимации — A намеренно почти неподвижен.
- QR: появляется fade 200ms.
- Reduced motion: все переходы мгновенные, подсветка завершения остаётся статичной 2 секунды.

### 14. Light mode

Тёплый-нейтральный белый, не кремовый (`#F6F6F3` почти без хромы), чтобы фото с любым балансом белого выглядели правильно. Чернильный текст. Зелёный редкий.

### 15. Dark mode

«Галерея после закрытия»: глубокий зеленовато-угольный фон (`#151716`), фото как подсвеченные экспонаты, серая подпись. Spot-зелёный становится светлым шалфеем `#93C4B2`. Без теней, глубина — разницей фона и surface.

### 16. Сильные стороны

- Лучшая читаемость и самая низкая доступностная рисковость.
- Фото любого качества выглядят достойно: интерфейс не спорит с ними.
- Пустое состояние не выглядит пустым благодаря типографике.
- Проще всего реализовать на shadcn: в основном токены и типографика.

### 17. Потенциальные проблемы

- Риск «красиво, но холодно» — ровно то, за что владелец критиковал v1 (не хватало «лёгкости и души»).
- Serif-антиква легко уводит в «свадебное приглашение» или «люкс»; нужна дисциплина: serif только для названий и цитат.
- Слабее всего как бренд: без логотипа его легко спутать с хорошим блогом.
- Тонкие линии и много воздуха на маленьком телефоне съедают первый экран — на 320px поля нужно сжимать.

## 5. Direction B — «Відбиток»

### 1. Название

**«Відбиток»** (Print). Тёплый и tactile, с лёгкими ассоциациями с физическими фотографиями.

### 2. Главная идея

Каждый вклад гостя — **отпечаток**: фото получает белое поле, как матовый отпечаток из лаборатории, и лежит на тёплой поверхности стола. Загрузка — это «отдать плёнку в проявку»: файлы уходят в **конверт**, а возвращаются отпечатками. Физичность выражена одним приёмом (белое поле + реальная тень на столе), а не набором декора.

Чем B отличается от отвергнутой v2 (scrapbook): нет скотча, нет рукописных шрифтов, нет наклеек и «ягодных» цветов, нет поворотов в рабочих экранах. Поворот и наложение разрешены только в двух «моментах» (см. п. 8).

### 3. Визуальный характер

Тёплая серо-бежевая «столешница» (`#ECE7DF`) — темнее кремового, чтобы белые отпечатки на ней читались как предметы. Мягкие реальные тени (одна, короткая). Жёлтый цвет конверта фотолаборатории как главный акцент действия, кораллово-красный — как «красный свет» и маркер.

### 4. Эмоция

Тепло, ностальгия без ретро, «приятно держать». Гость чувствует, что отдаёт что-то ценное, а не «загружает файлы».

### 5. Палитра

| Роль | Light | Dark | Контраст Light / Dark |
| --- | --- | --- | --- |
| background («стол») | `#ECE7DF` | `#1C1916` | — |
| surface («отпечаток», белое поле) | `#FBFAF7` | `#27231F` | — |
| primary text | `#27231F` | `#F1ECE4` | на bg 12.67 / 14.88; на surface 14.94 / 13.26 |
| muted text | `#675F56` | `#B1A89C` | на bg 5.10 / 7.46; на surface 6.01 / 6.65 |
| border (декоративный) | `#D8D0C4` | `#3B352F` | на surface 1.46 / 1.29 |
| input edge | `#8C8478` | `#7A7268` | на surface 3.54 / 3.29; на bg 3.00 / 3.70 |
| primary accent (жёлтый конверт) | `#E3B23C` | `#E8BC52` | **только заливка** в light (на surface 1.88); текст на нём `#27231F` 7.95 / 8.72; в dark как текст 9.79 |
| secondary accent (коралл «красный свет») | `#B9503A` | `#E8907A` | как текст на surface 4.71 / 6.46; белый на нём 4.92 |
| success | `#3B7441` | `#8BC48F` | на surface 5.35 / 7.72 |
| warning | `#94600F` | `#EAB45F` | на surface 5.11 / 8.31 |

Ограничения палитры: жёлтая кнопка на светлом фоне имеет контраст границы 1.59 — это допустимо (WCAG не требует контраста фона кнопки, если её определяет текст), но **focus ring в light — чернильный** `#27231F` (12.67 на bg), не жёлтый. Ссылки — цвет текста с подчёркиванием, не жёлтые. Коралл и destructive близки по тону: коралл никогда не используется для ошибок и удаления; destructive всегда с иконкой и словом. `input` на bg ровно 3.00 — на границе; поля ставить на surface, не на стол.

Осознанная проверка на шаблонность: B тёплый, но избегает «кремовый + serif + терракота». Фон темнее и серее кремового, главный акцент — жёлтый, а не терракота, serif-display не используется.

### 6. Typography direction

- **Основной: Commissioner** (Kostas Bartsokas). Гуманистический гротеск с осью `FLAR` (раскрытие окончаний штрихов) и `VOLM`. Для UI — `FLAR 0` (чистый, читаемый), для заголовков — `FLAR ~50`: мягкие расширяющиеся окончания дают «тёплую», почти рукотворную ноту без рукописного шрифта. Одна гарнитура — и характер, и инструмент.
- **Акцидентный: Literata Italic** (TypeTogether), только для подписей к отпечаткам («Додала Марта, 21:10») и для текстовых сообщений гостей. Курсив Literata читается как подпись на обороте фотографии — но это книжная гарнитура, а не имитация почерка.
- **Шкала:** 13 / 15 / 17 / 20 / 26 / 34 / 44 / 60. Заголовки Commissioner 600, `FLAR 50`; body 400.

### 7. Shape language

- Радиусы: контролы 10px, отпечатки 3px (бумага, а не карточка), диалоги 16px, конверт загрузки 16px сверху.
- Белое поле отпечатка: 6% от ширины фото (минимум 6px, максимум 16px), снизу поле в 2 раза шире — там подпись. Это и есть главный формальный приём B.
- Тени: одна «настольная» тень для отпечатков `0 1px 1px rgb(39 35 31 / 0.10), 0 6px 14px -6px rgb(39 35 31 / 0.22)`; в dark вместо тени — светлое поле отпечатка (`surface` светлее стола) и 1px внутренний highlight.
- Границы почти не используются: предметы отделяются тенью и полем.

### 8. Как используются фотографии

- **Отпечаток с полем** — везде, где фото показано как «момент»: guest-галерея, обложка коллекции, success-состояние.
- **Поворот ±1.5° и наложение** — только в двух местах: (1) стопка «Ви додали 12» на экране успеха гостя, (2) обложка коллекции на dashboard (стопка из 3 последних фото). Нигде больше.
- **Запрещено в admin-галерее:** поворот, наложение, разные размеры полей. Admin-галерея — ровная сетка отпечатков без нижнего поля (подпись по фокусу), чтобы работать быстро.
- **Масштабная оговорка:** на 100+ фото поля съедают ~12% площади; для admin есть «плотный» режим без полей.

### 9. Стиль компонентов

- Primary-кнопка: жёлтая заливка, чернильный текст 16/600, высота 52 (guest 56), радиус 10.
- Secondary: surface + 1px `input`.
- Inputs: на surface, 1px `input`, радиус 10.
- Tabs: «сегменты» на surface с поднятым активным сегментом.
- Свои компоненты: `Print` (фото + поле + подпись), `PrintStack` (стопка, только для двух мест), `Envelope` (контейнер очереди загрузки снизу экрана: язычок с количеством файлов, разворачивается в список).
- Text-вклад: отпечаток без фото — карточка на «бумаге» с курсивом Literata.

### 10. Navigation

- **Guest:** без навигации. Если есть галерея — сегмент «Додати / Подивитися» в шапке не нужен: галерея просто под главным действием.
- **Admin:** шапка с wordmark и аккаунтом; внутри коллекции — сегменты (Вміст, Тексти, Доступ, Скарги, Налаштування). На телефоне — горизонтальный скролл сегментов.

### 11. Guest-side

Первый экран — «стол»: название коллекции Commissioner 34–44px, под ним стопка 2–3 отпечатков из галереи (если разрешена) или пустой отпечаток-рамка, большая жёлтая кнопка «Додати фото». Конверт появляется снизу, как только выбран первый файл.

### 12. Admin-side

Dashboard — коллекции как стопки отпечатков (единственное место с наложением в admin). Внутри коллекции — ровная сетка, плотный режим по умолчанию для больших коллекций (>60 элементов).

### 13. Motion

- Выбор файлов: thumbnail «опускаются» в конверт (translateY + scale, 220ms, stagger 30ms, максимум первые 6, остальные просто появляются в счётчике).
- Upload progress: язычок конверта заполняется жёлтым; на каждом файле — тонкая полоса.
- Success: отпечатки «выходят» из конверта и ложатся стопкой (400ms, один раз за сессию загрузки). Фото «проявляются» (fade from warm grey 300ms).
- Новый контент у admin: появление без движения, только fade.
- Создание коллекции: пустой отпечаток с названием ложится на стол (250ms).
- QR: печатается как отпечаток (fade + маленький сдвиг 8px).
- Reduced motion: конверт и стопка статичны, проявление — мгновенно, успех показывается текстом и статичной стопкой.

### 14. Light mode

Дневной стол у окна: тёплый серо-бежевый, белые отпечатки, жёлтые действия.

### 15. Dark mode

**Тёмная комната:** коричнево-чёрный фон `#1C1916`, отпечатки темнее бумаги, акцент — янтарный «безопасный свет» `#E8BC52`, коралл светлее. Это самая самостоятельная тёмная тема из четырёх: у неё есть собственная метафора, а не инверсия.

### 16. Сильные стороны

- Сильнее всех передаёт «фото, воспоминания, тепло, физические фото».
- Конверт — понятная метафора очереди загрузки и частичного успеха («3 відбитки не вийшли»).
- Тёмная тема с собственной историей.
- Гостю приятно: это ощущается как подарок, а не форма.

### 17. Потенциальные проблемы

- **Главный риск — скатиться в scrapbook**, который владелец уже отверг (v2). Требует жёсткого правила «поворот только в двух местах».
- Белые поля уменьшают полезную площадь на маленьком телефоне и в большой admin-галерее.
- Жёлтая кнопка на светлом фоне слабо выделяется по контрасту формы; держится на цвете и размере.
- Метафора «отпечаток» хуже подходит документам (DOCX/XLSX) — их приходится тоже «печатать».
- Тени и поля — больше работы в Storybook и в визуальных регрессиях.

## 6. Direction C — «Контактний аркуш»

### 1. Название

**«Контактний аркуш»** (Contact sheet). Современный, немного экспериментальный, но сдержанный.

### 2. Главная идея

Событие — это **плёнка**: каждый вклад становится кадром с номером в порядке появления. Коллекция — контактный лист: строгая сетка кадров, номера, время. Выбор и «новое» помечаются как **восковым карандашом**: красно-оранжевым кругом/подчёркиванием, как фотографы отмечали лучшие кадры на контактных листах. Экспериментальность — в системе (номера, время, отметки, сетка как интерфейс), а не в эффектах.

### 3. Визуальный характер

Светло-серый фон, белые «листы», очень точная сетка с одинаковыми промежутками, номер кадра у каждого элемента. Моноширинные цифры только для настоящих данных (номер кадра, время, размер). Один выразительный жест — отметка карандашом. Остальное строгое.

### 4. Эмоция

Ощущение процесса и живого события: «плёнка набирается», видно, как вклады прибывают. Современно, слегка «профессионально», но без холодности за счёт отметок и времени.

### 5. Палитра

| --- | --- | --- | --- |

| surface («лист») | `#FFFFFF` | `#1C1F1D` | — |
| primary text | `#141614` | `#E9EBE6` | на bg 16.04 / 15.14; на surface 18.19 / 13.85 |
| muted text | `#5A5D58` | `#9CA099` | на bg 5.90 / 6.84; на surface 6.68 / 6.26 |

Роли: карандаш — выбор, отметка «нове», focus ring, активный таб, главная кнопка гостя. Фиолетовый — ссылки и информационные состояния (не градиент, сплошной приглушённый тон). Primary-кнопки в admin — чернильные, чтобы карандаш оставался редким. Риск: карандаш и destructive — оба тёплые красные; destructive сдвинут в малиновый (`#A3203A`) и всегда с иконкой корзины и словом, а карандаш никогда не используется для ошибок.

### 6. Typography direction

- **Основной: Geologica** (Monokrom, Норвегия). Геометрично-гротескная гарнитура с осями `SHRP` (острота окончаний), `CRSV` (курсивные формы) и `slnt`. В UI — `SHRP 0`, нейтрально; в заголовках — `SHRP 60–100`: острые срезы дают «современный, слегка экспериментальный» голос на одной и той же гарнитуре. Кириллица от того же дизайнера, не добавлена потом.
- **Данные: Geist Mono** — только для номера кадра, времени, размеров, счётчиков. `frontend-design` предупреждает, что моно для мелких подписей — шаблонный признак; здесь это оправдано, потому что номер кадра — реальная последовательность (порядок поступления), а время — реальные данные, которые нужно сравнивать по столбцам. Нигде больше моно не используется.
- **Шкала:** 12 (моно-метки) / 14 / 16 (body) / 19 / 24 / 32 / 44 / 64. Заголовки Geologica 600, `SHRP 80`, лёгкий отрицательный трекинг −1% только на ≥44px.

### 7. Shape language

- Радиусы: контролы 8px, кадры 2px, листы 4px, диалоги 12px. Почти прямые формы — «бумага и плёнка».
- Сетка как граница: кадры разделены 1px линиями сетки листа (`border`), а не промежутками с тенями.
- Тени: только для всплывающих слоёв (одна). Листы — без тени, выделены цветом.
- Отметка карандашом: SVG-контур неровного круга/подчёркивания 2.5px, единственная «нерегулярная» форма во всей системе.

### 8. Как используются фотографии

- **Контактная сетка:** квадратные или 3:2 кадры одинакового размера с номером и временем под каждым. Это главный вид admin-а и guest-галереи.
- **Лента события:** горизонтальная временная шкала (scrubber) по часам события — «19:00 · 20:00 · 21:00» как отметки на плёнке; клик переносит к кадрам этого часа. Работает и для гостя, и для admin.
- **Крупный кадр:** просмотр — один кадр на тёмном поле с номером «#086» и подписью.
- **Запрещено:** поворот, коллаж, наложение. Асимметрия допускается только на guest-первом экране (большой последний кадр + колонка маленьких).
- Обрезка в квадрат допустима в сетке (это контактный лист), оригинальные пропорции — в просмотре и в режиме «рядами».

### 9. Стиль компонентов

- Guest-кнопка: карандашная заливка, белый текст 17/600, 56px, радиус 8. Admin primary — чернильная.
- Inputs: 1px `input`, радиус 8, метка над полем.
- Tabs: текст + карандашное подчёркивание (SVG-штрих) под активным.
- Badges: моно-цифры в рамке 1px для счётчиков; статус — точка + текст.
- Upload: каждый файл получает номер кадра ещё до загрузки (локально «#087–#116»), прогресс — заполнение рамки кадра снизу вверх.
- Свои компоненты: `FrameGrid` (контактная сетка с номерами), `FrameLabel` (номер + время, моно), `MarkerHighlight` (SVG-отметка), `EventTimeline` (scrubber по времени).

### 10. Navigation

- **Guest:** без навигации; scrubber времени появляется только в галерее при >40 элементах.
- **Admin:** шапка; внутри коллекции — табы; на lg+ слева тонкая колонка-«поле листа» с номерами часов (timeline), справа сетка. Горячие клавиши в admin: стрелки по кадрам, `x` — выбрать, `Delete` — удалить с подтверждением (дополнение к кнопкам, не замена).

### 11. Guest-side

Первый экран: название Geologica 32–44px, строка «86 кадрів · остання о 21:10» (если галерея видна), большой последний кадр, карандашная кнопка «Додати фото». После загрузки гость видит **свои номера кадров**: «Ваші кадри #087–#116» — конкретно, проверяемо, даёт ощущение участия. В contribution-only режиме показываются только свои кадры с той же нумерацией.

### 12. Admin-side

Самое сильное место C. Плотная сетка, номера, фильтры, мульти-выбор карандашом, timeline. Ощущение «мощного, но простого инструмента» без CRM-таблиц.

### 13. Motion

- Новый кадр: появляется в конце листа, номер «щёлкает» (смена цифры 150ms), без сдвига остальных.
- Upload progress: рамка кадра заполняется снизу вверх (transform scaleY, не высота), счётчик моно-цифрами.
- Выбор: карандашный круг рисуется (stroke-dashoffset, 180ms).
- Success: последний кадр получает карандашную отметку «готово» и счётчик «30 з 30».
- Создание коллекции: появляется пустой лист с кадром «#001» (пунктир) — приглашение к первому вкладу.
- QR: появляется без анимации; при rotate старый QR перечёркивается карандашом (200ms) перед заменой.
- Hover: только смена рамки на кадре; ничего не «подпрыгивает».
- Reduced motion: отметки появляются целиком, цифры меняются без анимации.

### 14. Light mode

Светло-серый стол, белые листы, чёрный текст, редкий красно-оранжевый карандаш. Похоже на контактный лист на световом столе днём.

### 15. Dark mode

**Световой стол ночью:** почти чёрный зеленоватый фон, кадры светятся, номера серые, карандаш становится светлым персиковым `#F08766`, фиолетовый — лавандовым. Фото на тёмном выглядят сильнее всего — для галереи это выгодно.

### 16. Сильные стороны

- Лучше всех масштабируется на большие коллекции и на admin.
- Номера кадров и время решают реальные задачи: «где мои фото», «что нового», «сколько загружено».
- Отличается от любого SaaS и от фото-соцсетей; узнаваем по сетке и отметкам.
- Не зависит от качества фото: сетка выравнивает случайные кадры с вечеринки.
- Пустое состояние — пустой кадр «#001» — понятное приглашение.

### 17. Потенциальные проблемы

- Номера кадров — новая концепция для гостя; нужно проверить, что «#087» не путает (возможно, показывать номера только в admin и в «ваших кадрах»).
- Номер кадра нужен стабильный: требуется порядковый номер в коллекции на backend (поле в модели данных, не только вычисление на клиенте) — это решение для архитектуры.
- Удалённые кадры создают «дыры» в нумерации; надо решить, это честно (как плёнка) или путает.
- Слегка «профессиональный» тон может показаться холодным для семейных событий.
- Две гарнитуры с переменными осями — бюджет шрифтов выше, чем у A.

Пустая коллекция — один пунктирный кадр «#001». На телефоне кадры уходят под название и скроллятся горизонтально (видимая полоса скролла и кнопка «Відкрити»).

## 7. Direction D — «Квиток»

### 1. Название

**«Квиток»** (Ticket). Узнаваемая бренд-идентичность.

### 2. Главная идея

Гостевая ссылка — это **вход на событие**. Самый узнаваемый объект Stepler — то, что гость держит в руках до всего остального: QR на столе, на экране, в чате. D делает из него фирменную форму: **отрывной квиток** — прямоугольник с полукруглыми вырезами по бокам и линией отрыва. Эта форма повторяется в трёх местах (QR-постер, гостевой вход, обложка коллекции) и больше нигде. Плюс один фирменный цвет-пара (глубокая слива + шафран) и плакатная узкая гарнитура, как на афишах.

### 3. Визуальный характер

Смелее остальных: крупные узкие заголовки, насыщенный тёмный цвет как поверхность гостевой шапки, шафрановые акценты. При этом рабочие экраны (галерея, списки) спокойные — бренд живёт в «моментах входа», а не везде.

### 4. Эмоция

Предвкушение и причастность: «я на этом событии, у меня есть квиток». Праздник без украшательства.

### 5. Палитра

| background | `#F3F0F3` | `#1B1321` | — |
| surface | `#FFFFFF` | `#261B2D` | — |
| primary text | `#25192B` | `#F3EDF5` | на bg 14.82 / 15.70; на surface 16.77 / 14.29 |

| secondary accent | шафран `#F1B43E` | лаванда `#D3B6E2` | light: **только заливка** (на surface 1.85), тёмный текст на нём 9.05; dark: на surface 9.05 |

Логика тем: в light слива — главный цвет действий и гостевой шапки-квитка, шафран — «штамп» (QR-рамка, отметка «додано»). В dark слива становится комнатой (фон `#1B1321`), а шафран — светом и главным действием. Пара сохраняется, роли меняются — тёмная тема не инверсия, а «вечер того же события». Шафран и warning близки — warning всегда с иконкой и текстом, шафран не используется для предупреждений.

### 6. Typography direction

- **Display: Sofia Sans Extra Condensed** 700–800 (Lettersoup, Болгария). Узкая плакатная гарнитура, как на афишах и билетах. Объективное преимущество для украинского: узкий рисунок помещает длинные слова («Фотографії», «Налаштування») в крупный кегль на 320px — у остальных направлений здесь самые жёсткие компромиссы. Кириллица — родная для дизайнеров (болгарская школа кириллического шрифта).
- **UI и текст: Sofia Sans** (тот же суперсемейство, нормальная ширина). Одна семья в разных ширинах — цельно и экономно.
- **Шкала:** 13 / 15 / 17 / 20 / 28 / 40 / 56 / 88 (display). Display сжатый 800 с межстрочным 0.95; UI 400/600.
- Правило: display только для названий событий, `h1` и чисел-итогов («27 додано»). Никогда — для кнопок и меток.

### 7. Shape language

- **Квиток:** прямоугольник радиус 14px с двумя полукруглыми вырезами 12px по боковым сторонам на линии отрыва и пунктирной линией между частями (CSS `mask` с radial-gradient — без картинок). Используется в 3 местах: QR, гостевой вход (шапка), обложка коллекции в dashboard.
- Остальное: контролы 12px, фото 8px, диалоги 20px. Мягче, чем A и C.
- Тени: одна для квитка (`0 10px 30px -14px rgb(75 39 85 / 0.35)`), одна для всплывающих слоёв. В dark — без тени, квиток светлее фона.
- Границы: только у полей и разделителей списков.

### 8. Как используются фотографии

- Обложка коллекции — главная часть квитка (фото в «корешке» квитка или типографическая обложка, если фото нет).
- Галерея — спокойная masonry с радиусом 8px, без поворотов и коллажей.
- **Лёгкое наложение** разрешено только в success-состоянии гостя: 3 загруженных фото выглядывают из-за квитка «Додано 27». Нигде больше.
- Подписи — Sofia Sans 13px muted.

### 9. Стиль компонентов

- Primary: сливовая заливка (dark — шафрановая), 52px (guest 56), радиус 12, Sofia Sans 17/600.
- Secondary: outline 1.5px сливовый текст.
- Inputs: 1px `input`, радиус 12.
- Tabs: «пилюли» на surface с заливкой активного сливовым 10%.
- Badges: маленький шафрановый «штамп» для «нове» (тёмный текст), остальные статусы — точка + текст.
- Свои компоненты: `Ticket` (форма с вырезами, слоты «корешок» и «тело»), `TicketQr`, `StampBadge`.
- Upload: панель снизу как отрывная часть квитка — «корешок» с количеством и общим прогрессом.

### 10. Navigation

- **Guest:** шапка-квиток с названием события; дальше без навигации.
- **Admin:** шапка; на lg+ — левая узкая колонка со списком коллекций (переключение без возврата на dashboard), внутри коллекции — табы. На телефоне — список коллекций как отдельный экран (текущее правило «без section nav» сохраняется).

### 11. Guest-side

Первый экран — квиток во всю ширину: сверху сливовая часть с названием Extra Condensed 56px и датой, линия отрыва, снизу белая часть с одной строкой «Додайте фото, відео або побажання» и кнопкой. Это одновременно бренд и понятная инструкция. Ниже — галерея или строка про contribution-only.

### 12. Admin-side

Dashboard — коллекции как квитки (обложка + название + счётчик). Внутри коллекции бренда почти нет: спокойная галерея, таблица ссылок, квиток только в табе «Доступ» (QR).

### 13. Motion

- Создание коллекции: квиток «печатается» — проявляется сверху вниз (clip-path 300ms), один раз.
- Генерация QR: QR-модули появляются диагональной волной (240ms) — единственная «эффектная» анимация продукта, потому что QR — фирменный объект.
- Upload: корешок заполняется шафраном; по завершении — «штамп» «Додано» (scale 1.1 → 1, 180ms).
- Success: квиток «надрывается» по линии (смещение 6px + поворот 1°, 250ms) — момент «я внёс вклад».
- Новый контент у admin: fade.
- Reduced motion: квиток и QR появляются целиком; штамп без масштаба; надрыв показан статично.

### 14. Light mode

Светлый лилово-серый фон, белые поверхности, сливовые действия, шафрановые штампы. Узнаваемо с первого взгляда: ни у одного известного фото-сервиса нет такой пары.

### 15. Dark mode

«Вечер события»: сливовая ночь `#1B1321`, шафран — свет и главное действие, лаванда — ссылки. Фото на сливовом фоне выглядят теплее, чем на чёрном.

### 16. Сильные стороны

- Сильнейший бренд: квиток + слива/шафран + узкие заголовки легко узнать на постере, в чате, на экране.
- Квиток связывает физический мир (QR на столе, будущие постеры/наклейки из post-MVP) с цифровым.
- Узкая гарнитура лучше всех справляется с длинными украинскими словами в крупных кеглях.
- Бренд сосредоточен в 3 местах, поэтому рабочие экраны остаются простыми.

### 17. Потенциальные проблемы

- **Путаница с билетными сервисами:** гость может подумать, что это продажа билетов или регистрация на событие. Это прямо противоречит цели «не ощущение регистрации». Нужно проверить на людях.
- Сливовый цвет и шафран — сильный вкусовой выбор; может не подойти корпоративным событиям или поминальным/серьёзным поводам.
- Квиток-маска — нестандартная форма: сложнее с фокусом (outline по маске), с RTL не актуально, но с длинными названиями и масштабированием текста надо тестировать.
- Узкая гарнитура в больших объёмах утомляет — правило «только display» обязательно.
- Бренд завязан на метафору события; для post-MVP сценариев (не события: семейный архив, команда) квиток подходит хуже.

### 8.2 Объективные ограничения (не вкус)

- Все четыре палитры проходят WCAG AA для текстовых пар в обеих темах; цвета, которые не проходят как текст (жёлтые/шафрановые), помечены «только заливка» и требуют правила в токенах.
- Все восемь шрифтов: OFL, полная украинская кириллица, подключение через `next/font`. Любое направление реализуемо на текущем стеке без новых библиотек.
- C требует решения в модели данных (стабильный порядковый номер элемента в коллекции); остальные — нет.
- B и D добавляют собственные нестандартные компоненты (Envelope, PrintStack / Ticket-маска), которые нужно покрыть Storybook, reduced-motion stories и axe — это объём работы, а не риск.

### 8.3 UX considerations

- Гость: A проще всех; B и D добавляют эмоцию в момент успеха (стопка, надрыв), что, вероятно, повышает удовлетворение, но не скорость. У D есть реальный риск неверного прочтения («это билет / регистрация»), его нужно проверить на 5 людях с телефоном.
- Admin: C решает реальные задачи (порядок, время, «что нового», мульти-выбор) лучше всех; B наименее удобен на 100+ элементах без «плотного» режима.
- Не все события радостные (похороны, памятные встречи): A и C нейтральны по тону; B тёплый, но уместен; D праздничный и уместен хуже всего.
- Post-MVP сценарии без события (семейный архив, команда): A, B и C переносятся; квиток D — хуже.

### 8.4 Субъективные предпочтения (решает владелец)

- Насколько продукт должен быть «смелым»: A самый тихий, D самый громкий.
- Serif или нет: A — serif-голос, B — serif только в подписях, C и D — без serif.
- Слива/шафран D и жёлтый B — сильные вкусовые решения; зелёный A и карандаш C — спокойнее.
- Насколько допустима ностальгия: B намеренно ностальгичен, C — «профессиональная» ностальгия (контактный лист), A и D — нет.

### 8.5 Рекомендация

С учётом всех критериев я бы выбрал **C «Контактний аркуш» как основу**: он лучше всех держит admin, не зависит от качества фото, отличается от SaaS без декора и сохраняет сдержанность, которую владелец ценил в v1, но с характером (номера, время, отметки), которого v1 не хватало. Из B стоит взять один приём — **тёплый момент успеха гостя** (стопка «ваших кадров»), из D — идею **QR как фирменного объекта** (без формы квитка). Второй кандидат — **B**, если важнее эмоция, чем инструментальность.

Перед окончательным выбором предлагаю проверить C и B одним экраном — guest upload на реальном телефоне (кликабельный прототип, 5 человек, задача «добавь 3 фото»). Это не решение за владельца: все четыре направления реализуемы и соответствуют ограничениям.

## 9. Открытые продуктовые и UX-вопросы

Эти вопросы меняют дизайн экранов. Я не решал их молча; для каждого — варианты и вариант по умолчанию, если владелец не хочет решать сейчас.

**9.1 Имя гостя: где спрашивать и показывать ли публично.** D6 зафиксировал необязательное поле «Як вас звати?», не публичное автоматически. Открыто:
- (a) спросить до выбора файлов (одно поле над кнопкой) — +1 шаг для всех;
- (b) спросить после первой загрузки («Підписати ваші фото?») — без трения, имя появится не у всех;
- (c) спросить один раз за guest session и запомнить.
Публичность в общей галерее: (1) никогда, только admin; (2) настройка коллекции; (3) по выбору гостя. По умолчанию предлагаю (b)+(c) и публичность (2) с выключенным значением. Подписи «Додала Марта» во всех направлениях зависят от этого решения.

**9.2 Режим видимости в гостевом UI.** В contribution-only гость не видит чужого. Как ему это объяснить и что показывать вместо галереи:
- (a) одна строка «Ваші файли побачить лише організатор» + список своих загрузок;
- (b) только подтверждение без списка;
- (c) счётчик «Уже додали 86» без самих фото (раскрывает объём активности — может быть нежелательно).
По умолчанию (a). Также: если ссылка view-only, первый экран должен быть галереей, а не кнопкой — нужно согласовать.

**9.3 Обложка коллекции.** A и D сильнее с обложкой, но admin в MVP не загружает контент (D14). Варианты: (a) без обложки — типографическая; (b) admin выбирает обложку из гостевых фото; (c) admin загружает обложку (новый тип загрузки, расширяет MVP). По умолчанию (a), с (b) как ближайшее улучшение.

**9.4 Дата и место события.** Editorial-заголовки (A, D) выглядят естественно с датой («14 вересня, Львів»), но в модели коллекции есть только название и описание. Варианты: (a) не показывать; (b) добавить необязательную дату события; (c) использовать дату создания коллекции. По умолчанию (a); (b) — маленькое изменение модели, но это продуктовое решение.

**9.5 Сообщения о больших видео.** Лимит 2 GB без ограничения длительности, гость на мобильной сети. Варианты: (a) ничего не говорить заранее, показывать прогресс и оставшееся время; (b) мягкое предупреждение при выборе файла > 500 MB («Великий файл — краще через Wi-Fi»); (c) предупреждать, если браузер сообщает тип сети `cellular` (Network Information API есть не во всех браузерах — ненадёжно). По умолчанию (a)+(b). Порог — нужно решить.

**9.6 Offline и retry.** Что происходит, когда сеть пропала:
- (a) автоматический retry с паузой при восстановлении сети, ручная кнопка как запасной вариант;
- (b) только ручной retry.
Отдельно: переживает ли очередь закрытие вкладки. Возобновление после закрытия требует multipart/resumable upload и хранения очереди в браузере — это вопрос архитектуры, не дизайна. По умолчанию (a) в пределах открытой вкладки + предупреждение `beforeunload`; возобновление после закрытия — отдельное решение.

**9.7 Текстовый вклад: равноправное действие или вторичное.** Варианты: (a) вторичная ссылка под главной кнопкой (все направления сейчас так); (b) две равные кнопки «Фото і відео» / «Повідомлення»; (c) поле текста прямо на первом экране. Если `canUploadFiles = false`, а `canSubmitText = true`, текст становится главным действием — дизайн это поддерживает, но нужен пример копирайта.

**9.8 Где гость удаляет своё и где жалуется.** `canDeleteOwn` и жалобы требуют входа в элемент. Варианты для удаления: (a) раздел «Мої файли» под галереей; (b) меню на каждом своём элементе в галерее. Для жалобы: пункт «Поскаржитися» в меню просмотра элемента (чужого). По умолчанию (a) + меню просмотра для жалобы.

**9.9 Жалобы у admin.** Отдельный таб «Скарги» в коллекции (как в макетах) или общий список на dashboard? При 3 коллекциях на аккаунт достаточно таба, но счётчик непрочитанных стоит показать на dashboard. Нужно решить, что admin видит (причина, описание) — данные уже определены в F2.

**9.10 Язык на гостевой странице.** Гость может не читать по-украински. Варианты: (a) язык браузера (`Accept-Language`), без переключателя; (b) язык браузера + видимый переключатель УКР/ENG в шапке; (c) язык задаёт admin для коллекции. По умолчанию (b) — в макетах выше предусмотрено место.

**9.11 Тема на гостевой странице.** (a) следует системе гостя; (b) admin выбирает светлую/тёмную для коллекции (часть post-MVP кастомизации 24.3). По умолчанию (a).

**9.12 Нумерация кадров (только для C).** Показывать номера гостям или только admin; что делать с «дырами» после удаления. Если выбран C — нужно решить до модели данных.

**9.13 Прев’ю, которое ещё не готово.** Thumbnail и poster создаются асинхронно, HEIC не показывается браузером. Что видит гость сразу после загрузки: (a) локальное прев’ю из файла (из браузера, пока страница открыта); (b) плейсхолдер «Готується прев’ю». По умолчанию (a) с fallback (b).

## 10. Следующий этап

После выбора направления (или осознанной комбинации):

1. design principles выбранного направления (5–7 правил, включая «где разрешён поворот/наложение/бренд»);
2. tokens: color (light/dark, с таблицей контраста, как в `docs/ux/design-system.md`), type scale, spacing, radius, elevation, motion durations/easings;
3. component spec: какие shadcn-компоненты меняются и какие 3–5 собственных компонентов добавляются;
4. page layouts для 5 экранов и всех состояний (loading, empty, error, partial, permission denied, revoked/deactivated link);
5. responsive-спецификация по таблице брейкпоинтов;
6. interaction/motion spec с reduced-motion вариантами;
7. accessibility checklist для каждого компонента;
8. план реализации в Storybook (stories, play-тесты, axe, reduced-motion stories);
9. кликабельный прототип guest upload для проверки на телефоне;
10. ADR, если выбор меняет модель данных (C: номер кадра) или вводит новые шрифты.
