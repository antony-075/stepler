## 1. Принципы дизайна

1. **Событие — это плёнка.** Каждый вклад — кадр с номером и временем. Сетка, номер и время — не декор, а интерфейс: они отвечают на «где мои фото», «что нового», «сколько уже». Если элемент не является последовательностью, номер ему не дают.
2. **Сетка ровная, исключение одно.** Кадры одинакового размера, разделены линией сетки 1px, без теней, без поворотов, без наложения. Единственное место, где разрешены поворот (±1.5°), наложение и тень на кадре, — стопка «ваших кадров» на экране успеха гостя (`PrintStack`, из B). Больше нигде, включая dashboard.
3. **Карандаш редкий.** Красно-оранжевый `pencil` — только выбор, «нове», активный таб и главная кнопка гостя. Если на экране больше трёх карандашных пятен (кроме выбранных кадров), что-то лишнее. Карандаш никогда не означает ошибку. **Фокус — фиолетовый, никогда не карандаш** (решение владельца 2026-10-02: красно-оранжевая рамка вокруг поля читается как ошибка).
4. **Контент → действия → навигация.** Кадры занимают максимум площади; chrome — тонкая шапка и одна строка действий. Admin — инструмент, без атмосферы и иллюстраций; характер выражается сеткой, номерами и отметками.
5. **Одно действие у гостя.** Первый экран отвечает «что это» (название) и «что делать» (одна кнопка в зоне большого пальца). Всё остальное ниже или вторично.
6. **Плоско по умолчанию.** Глубина — только у того, что действительно лежит поверх контента (меню, диалог, toast, док над сеткой при прокрутке). Листы и кадры отделяются цветом и линией.
7. **Моно — только для данных.** Geist Mono — номер кадра, время, длительность, размер, счётчики. Ни для подписей «для вида», ни для заголовков, ни для кнопок.
8. **Состояние словами, а не только цветом.** Каждый статус (в черзі, завантажується, додано, не вдалося, вибрано, нове) дублируется иконкой или текстом и имеет доступное имя.

Анти-признаки, которых система избегает сознательно (из `frontend-design`): ALL CAPS-метки, eyebrow над каждым заголовком, «→» в кнопках, одинаковые rounded cards с одной тенью, градиентные пятна, строки метаданных, склеенные «·» в копирайте (разделитель — CSS-зазор между отдельными элементами, не символ в переводе).

## 2. Токены

Имена — CSS custom properties в `packages/ui/src/styles/globals.css`, экспортированные в Tailwind через `@theme inline`. Где возможно, сохранены имена shadcn (`--background`, `--card`, `--primary`…), чтобы shadcn-компоненты и существующие классы (`bg-card`, `text-muted-foreground`) продолжали работать после замены значений (раздел 10). Dark применяется под `prefers-color-scheme: dark` без `data-theme="light"` и под `data-theme="dark"` — механизм не меняется.

### 2.3 Spacing

Базовый шаг 4px. Шкала (Tailwind `--spacing: 0.25rem`, используются только эти значения):

`0 · 1px (линия сетки) · 2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64 · 80`

| Назначение | Значение |
| --- | --- |
| Gap контактной сетки | 1px (линия = фон `--border` под кадрами, как в артбордах) |
| Padding кадра (поле листа вокруг фото) | 6px сверху/по бокам, 4px снизу под подписью; 4px в плотном admin-режиме |
| Gutter страницы | 16 (base) / 24 (`sm`) / 32 (`lg`) / 40 (`2xl`) |
| Между блоками внутри секции | 12–16 |
| Между секциями | 32 (phone) / 48 (desktop) |
| Высота шапки | 44 guest (без рамки) / 56 admin (`border-b`) |

Отличие от v4: gutter `lg` 40 → 32 (сетка выигрывает колонку на 1024), `stepler-container` сохраняется с новыми значениями.

### 2.6 Elevation

C в основном плоский. Тень — у слоёв поверх контента и (решение владельца 2026-10-02) лёгкий «бумажный» подъём у карточек и панелей:

| Уровень | Light | Dark | Где |
| --- | --- | --- | --- |
| 0 flat | нет | нет | страница, кадры, шапка; карточки внутри карточки или диалога (без двойных теней) |
| card | `--shadow-card: 0 1px 2px rgb(20 22 20 / 0.04), 0 2px 8px rgb(20 22 20 / 0.05)`; при наведении на интерактивную карточку `--shadow-card-hover: 0 1px 2px rgb(20 22 20 / 0.06), 0 4px 14px rgb(20 22 20 / 0.08)` | нет: край 1px и более светлый лист | `Panel` (по умолчанию), карточки коллекций, тулбар, списки ссылок, секции настроек и «Акаунт», небезпечні зони |

### 2.8 Breakpoints

Viewport (Tailwind 4 + один свой): `base` 320–639 (отдельно проверяются 320 и 375–430) · `sm` 640 · `md` 768 · `lg` 1024 · `xl` 1280 · `2xl` 1536 · `3xl` 1920 (`--breakpoint-3xl: 120rem`). ## 3. Типографика

### 3.1 Семейства и роли

- **Geologica** (Monokrom, OFL) — весь текст интерфейса. Переменные оси: `wght` 100–900, `SHRP` 0–100, `CRSV` 0–1, `slnt` −12–0 (проверено по metadata Google Fonts).
- **Geist Mono** (Vercel, OFL) — только данные (раздел 3.3). Ось `wght` 100–900.

Решение по осям: **подключаем `wght` + `SHRP`; `CRSV` и `slnt` не подключаем.** Причина измерена: Geologica latin+cyrillic с `wght,SHRP` — 48.6 KB, со всеми четырьмя осями — 80.3 KB. Курсив и «курсивные формы» нужны были бы только цитатам гостей; в C цитата отличается рамкой кадра и размером, а не начертанием. Если позже понадобится `CRSV`, это +32 KB и проверка кириллицы в прототипе.

| Роль | Семейство | wght | SHRP | Где |
| --- | --- | --- | --- | --- |
| Wordmark «stepler» | Geologica | 600 | 100 | шапка (текстовый wordmark; `BrandMark` пересматривается в 5.18) |
| Display / h1 | Geologica | 600 | 80 | название коллекции, h1 страниц |
| h2 / h3 | Geologica | 600 | 60 | заголовки секций, «Ваші кадри» |
| Body, UI, кнопки, поля | Geologica | 400 / 600 (кнопки, метки) | 0 | весь остальной текст |
| Цитата гостя (текстовый вклад) | Geologica | 400 | 0 | `TextFrame` |
| Данные | Geist Mono | 400 / 500 (свой номер, счётчик в заголовке) | — | номер кадра, время, длительность, размер |

`SHRP` > 0 только на ≥ 19px: острые срезы на мелком кегле читаются как грязь (проверить в прототипе на Android с низкой плотностью — **не проверено**).

### 3.2 Шкала

Fluid только у display; остальное фиксировано. `text-wrap: balance` у h1–h3, `text-wrap: pretty` у абзацев.

| Token | base (320–767) | md (768–1279) | xl+ (≥1280) | line-height | letter-spacing | Использование |
| --- | --- | --- | --- | --- | --- | --- |
| `display` | 32px (28px при < 360) | 44px | 64px (только guest/landing) | 1.12 | −0.01em от 44px, иначе 0 | h1 guest, sign-in |
| `h1` | 28px | 32px | 44px | 1.15 | 0 / −0.01em на 44 | h1 admin («Колекції», название в коллекции 32) |
| `h2` | 19px | 24px | 24px | 1.2 | 0 | секции, название коллекции в dashboard |
| `h3` | 16px | 17px | 17px | 1.3 | 0 | подзаголовки панелей |
| `body-lg` | 17px | 17px | 17px | 1.5 | 0 | guest-тексты, главная кнопка гостя |
| `body` | 16px | 15px | 15px | 1.5 | 0 | admin body; поля всегда 16px (без iOS zoom) |
| `small` | 14px | 14px | 14px | 1.45 | 0 | подсказки, мета, кнопки `sm` |
| `caption` | 13px | 13px | 13px | 1.4 | 0 | подписи под кадром (имя), Terms-строка |
| `data` (mono) | 12px | 12px | 12px | 1.35 | 0 | номер, время в подписи кадра |
| `data-lg` (mono) | 16px / 20px | | | 1.2 | 0 | диапазон «#087–#116» в заголовке успеха |

Минимум 12px только для моно-цифр (крупный x-height, только цифры); текст словами — не меньше 13px. Длина строки ≤ 72 символа (`max-w-[60ch]` для абзацев).

### 3.3 Правила Geist Mono

Используется **только** для: номера кадра (`#087`), времени (`21:10`), длительности видео (`1:30`), размера файла (`8,6 МБ`), счётчиков в позиции данных (`12 з 30`, `116` у таба), часов на timeline (`20:00`), даты создания ссылки в списке ссылок. Всегда `font-variant-numeric: tabular-nums` (у Geist Mono и так равные цифры, правило нужно Geologica). Не используется для: URL гостевой ссылки (это текст для чтения — Geologica), названий файлов (длинные, читаются словами), кнопок, меток, заголовков. Числа внутри предложений («Додано 27 кадрів») — Geologica с `tabular-nums`, не моно.

### 3.4 Украинская специфика

- **Апостроф:** только `’` U+2019 (есть в обоих шрифтах; U+02BC в Geologica тоже есть, но клавиатуры вводят U+2019, а смешение ломает поиск). Правило копирайта и lint-проверка `messages/uk.json` на `'` и `ʼ` — в PR шрифтов.
- **Кавычки** «…», внутренние „…“; тире — `—` с неразрывным пробелом перед ним; многоточие `…` (одним символом), в состояниях загрузки тоже: «Завантаження…».
- **Числа:** через `Intl.NumberFormat('uk')` — разделитель тысяч неразрывный пробел (`1 234`), десятичная запятая (`8,6 МБ`); единицы `КБ МБ ГБ` через неразрывный пробел; время 24-часовое `21:10` через `Intl.DateTimeFormat`; даты словами «14 вересня». Номер кадра — `#` + минимум 3 цифры с ведущими нулями (`#007`), с 1000 — 4 цифры без нулей впереди. Множественное число через ICU (`кадр / кадри / кадрів`).
- **Длинные слова:** кнопки без фиксированной ширины; на 320px display 28px держит «Налаштування» в строке; пользовательские названия — `overflow-wrap: anywhere`; табы и чипы скроллятся, а не переносятся по слогам. `hyphens: auto` с `lang="uk"` **не включаем**, пока не проверено в Safari iOS и Chrome Android (поддержка словарей для `uk` не подтверждена); для собственных заголовков достаточно `balance`.
- **Без ALL CAPS** и без положительного трекинга; метки — sentence case.
- `translate="no"` на wordmark и номерах кадров.

### 3.5 Подключение

**Реализовано иначе, чем в наброске ниже** (решение 12.18, [ADR 0015](../architecture/decisions/0015-visual-direction-c-fonts-frame-numbers.md)): woff2 лежат в `packages/ui/src/fonts/` с OFL, apps/web подключает их через `next/font/local`, Storybook — через `@font-face`; один файл на семейство (latin + cyrillic), Geologica 40.8 KB, Geist Mono 29.2 KB. Набросок с `next/font/google` оставлен как история решения.

```ts
// apps/web/src/app/layout.tsx (заменяет Manrope и Unbounded)
import { Geologica, Geist_Mono } from 'next/font/google';
const geologica = Geologica({
  subsets: ['latin', 'cyrillic', 'cyrillic-ext'],
  axes: ['SHRP'],              // wght variable by default
  variable: '--font-geologica',
  display: 'swap',
});
const geistMono = Geist_Mono({
  subsets: ['latin', 'cyrillic'],
  variable: '--font-geist-mono',
  display: 'swap',
});
```

Измеренные woff2 (Google Fonts, 2026-10-02): Geologica `wght,SHRP` — latin 29.2 KB, cyrillic 19.4 KB, cyrillic-ext 13.4 KB (грузится по `unicode-range` только при нужных символах); Geist Mono — latin 23.1 KB, cyrillic 12.9 KB (только если в моно попадает «МБ»). Типичная guest-страница: **~72–85 KB**, в бюджете ~120 KB. Имена экспорта `Geologica`/`Geist_Mono` и приём `axes: ['SHRP']` нужно подтвердить сборкой (next/font падает на сборке при неверной оси — это проверка, а не риск). `--font-sans: var(--font-geologica), system-ui, …`, `--font-mono: var(--font-geist-mono), ui-monospace, …`; `--font-display` удаляется (display — тот же Geologica с другими осями через utility `font-display` → `font-variation-settings: 'SHRP' 80`). Storybook — см. 10.3.

## 4. Правила цвета

1. **Ink — главное действие admin.** «Нова колекція», «Поділитися», «Зберегти» — ink-заливка. В admin pencil-кнопок нет.
2. **Pencil — редкий и смысловой.** Разрешено: главная кнопка гостя («Додати фото», «Додати ще»), выбор кадра, отметка «нове», подчёркивание активного таба, прогресс загрузки (заливка рамки и общая полоса), `PencilMark` на итоговом счётчике успеха. Запрещено: focus ring и край поля в фокусе (решение владельца 2026-10-02), ошибки, предупреждения, удаление, ссылки, декоративные плашки, иконки в навигации, фоновые заливки больших площадей.
3. **Violet — ссылки, информация и фокус.** Текстовые ссылки (с подчёркиванием, не только цветом — 1.4.1), «Згорнути», info-Alert, тип документа «PDF» в кадре, **focus ring и край поля в фокусе везде** (`--ring` = `--link`). Не для кнопок и не для выбора. Фиолетовый и destructive по яркости совпадают (1.01 / 1.02), поэтому невалидное поле отличается не цветом, а текстом ошибки с иконкой; ring у невалидного поля — destructive.
4. **Destructive — только ошибки и удаление,** всегда с иконкой и словом. Крест на упавшем кадре — `--destructive`, не pencil (как в артборде `C-guest`).
5. **Success / warning** — текст, иконка, точка статуса, soft-фон Alert. Warning не ставится на `--hover`. Нет зелёных кнопок.
6. **Фото задают цвет.** Никаких цветных подложек под сеткой, никаких тонированных листов; плейсхолдер кадра с медиа — нейтральный `--muted`. Исключение (решение владельца 2026-10-02): пустые кадры до появления контента — в спокойном оттенке коллекции (2.1 «Відтінки кадрів»). Доминирующий цвет из thumbnail не используется (не нужен C и требует работы worker).
7. **Dark — «световой стол ночью»,** не инверсия: фон зеленовато-чёрный, листы на полтона светлее, popover ещё светлее вместо тени; pencil становится персиковым и получает тёмный текст на кнопке.
8. **Выбор никогда не только цветом:** рамка + `PencilMark` + иконка ✓ + `aria-pressed`/`aria-selected` + счётчик «Вибрано 3».

## 5. Компоненты

Небольшой набор. Поведение и доступность — от Radix/shadcn в `packages/ui`, вид — свой. Для каждого: анатомия → варианты → состояния → a11y → основа в `packages/ui`. Общие состояния всех интерактивных: default · hover (`--hover`/`--hover-card`, 120ms) · focus-visible (ring) · pressed (scale 0.98, только кнопки) · disabled (`--muted` + `--muted-foreground`, `aria-disabled` в диалогах) · loading (Spinner + текст «…», кнопка не меняет ширину).

### 5.1 Button

- **Анатомия:** [иконка `data-icon`] + текст; высота 44 (default), 56 (`guest`), 36 (`sm`, только pointer-плотные строки admin, никогда главное действие на тач).
- **Варианты (5):** `primary` (ink) · `pencil` (только guest primary) · `outline` (card + 1px input) · `ghost` (прозрачная, hover `--hover`) · `destructive` (заливка: в ConfirmDialog и одна кнопка в «Небезпечна зона» настроек, которая всегда открывает destructive ConfirmDialog — решение владельца 2026-10-02; в меню — пункт destructive). `link` → удаляется как вариант кнопки, ссылки — `TextLink`.
- **Состояния:** общие; `pencil` hover/active — `--pencil-hover`/`--pencil-active`.
- **A11y:** icon-only — `size="icon"` 44×44 + `aria-label`; текст не обрезается (кнопки растут, на 320 переносятся в колонку).
- **Основа:** `button.tsx` — restyle: радиус 8, ring 2px offset 2 вместо `ring-[3px] ring/70`, вариант `secondary` удалить (заменить `outline`), добавить `pencil` и size `guest`.

### 5.2 Поля: Input, Textarea, Field, Select, Checkbox, Switch, RadioGroup

- **Анатомия:** метка над полем (14/600) · поле 48px, 1px `--input`, радиус 8, фон `--card`, текст 16px · подсказка (14, muted) · ошибка (14, destructive, иконка `CircleAlert`, `role="alert"`).
- **Варианты:** нет; размер один. Textarea растёт до `max-h-72`, счётчик «4 812 / 5 000» моно справа под полем для текстового вклада.
- **Состояния:** hover — край `--foreground`; focus — ring; invalid — край и ring `--destructive`; disabled — `--muted`.
- **Checkbox** 20px, радиус 2, отмеченный — ink-заливка с белой галкой (не pencil: pencil — выбор кадров, а checkbox — настройка). **Switch** — трек 1px input, включённый трек ink. **Radio** — ink-точка.
- **A11y:** без изменений к v4 (Field wiring, RadioGroup через `aria-labelledby`, 44px строки).
- **Основа:** `input.tsx`, `textarea.tsx`, `field.tsx`, `select.tsx`, `checkbox.tsx`, `switch.tsx`, `radio-group.tsx`, `label.tsx` — только restyle.
- **Незбережені зміни (`UnsavedBar`, решение владельца 2026-10-02: muted-строка рядом с кнопками терялась):** пока в форме с явным «Зберегти» есть изменения, последним в форме стоит бар на `--warning-soft` с краем `--warning`, иконкой `TriangleAlert` и текстом «Є незбережені зміни — гості їх ще не бачать.», справа «Скасувати» и «Зберегти» (phone: стопкой, «Зберегти» сверху). Бар `sticky bottom-3`: пока форма на экране, кнопки под рукой. Текст — в polite live region, который смонтирован всегда, поэтому первое изменение объявляется. Без изменений бара и кнопок нет. Уход со страницы с несохранёнными изменениями спрашивает подтверждение (`useLeaveGuard`: закрытие/перезагрузка вкладки — диалог браузера, переход по ссылке внутри приложения — `confirm`; кнопка «Назад» браузера не перехватывается).

### 5.3 Sheet / Panel (замена Card)

- **Анатомия:** лист `--card`, радиус 4, без тени, 1px `--border` только если лист лежит на `--background` в dark (в light хватает контраста фона 1.07 + края контента — **проверить на тусклом экране**; при сомнении border включается в обеих темах). Секции разделены hairline.
- **Варианты:** `sheet` (контактная сетка, без padding — padding у кадров) · `panel` (настройки, ссылки: padding 16/24, строки `divide-y`).
- **Основа:** `card.tsx` → переименовать в `panel.tsx` (`Panel`, `PanelHeader`, `PanelTitle`, `PanelContent`), убрать `rounded-[20px]`, `shadow-card`, `font-display`. Временный re-export `Card` на время миграции.

### 5.4 Dialog, Sheet (bottom), ConfirmDialog

- **Dialog:** радиус 12, `--popover`, elevation 3, max-w 480; заголовок h2 19/600 SHRP 60; кнопки справа (desktop) / колонкой во всю ширину (phone, главная снизу).
- **BottomSheet (новый, на Radix Dialog):** на `base` вместо Dialog для действий гостя (текстовое сообщение, меню кадра в просмотре, «Мої файли»). Ручка 32×4 `--border`, верхние углы 12, `max-h: 90dvh`, safe-area снизу, `overscroll-behavior: contain`. Свайп вниз — дополнительный способ, кнопка «Закрити» обязательна.
- **ConfirmDialog:** без изменений поведения (фокус на «Скасувати», ожидание promise). Destructive-кнопка с иконкой корзины.
- **A11y:** `DialogTitle` всегда (sr-only если визуально не нужен), фокус-трап, Esc, возврат фокуса.
- **Основа:** `dialog.tsx`, `confirm-dialog.tsx` — restyle; `bottom-sheet.tsx` — добавить (Radix Dialog + свой вид; shadcn `drawer` на vaul не берём — новая зависимость ради одного жеста).

### 5.5 DropdownMenu

Пункты 44px, радиус 8 inset, hover `--hover-card`, focus — solid inset ring violet (`--ring`), destructive-пункт — destructive-текст + иконка. Контент `--popover`, elevation 2. Основа: `dropdown-menu.tsx` — restyle.

### 5.6 Tabs

- **Анатомия:** текст 15/600 + моно-счётчик 12 (`Кадри 126`); активный — foreground + карандашное подчёркивание (`PencilMark` variant `underline`); неактивный — muted. Нижняя линия списка 1px `--border`. Высота 48.
- **Поведение:** список скроллится горизонтально внутри себя, активный таб прокручивается в видимую область; состояние в URL (`?tab=access`).

## 6. Макеты страниц

Схемы — для структуры, не для пикселей. Цифры — токены выше. На всех страницах: skip link «Перейти до вмісту», один h1.

### 6.0 Каркас страницы admin (одно правило для всех)

Решение владельца 2026-10-02: ширина и левый край не должны меняться от страницы к странице (раньше настройки были колонкой 640 по центру, а коллекция — во всю ширину слева).

- **Один контейнер.** Каждая страница admin (dashboard, коллекция и её вкладки, настройки коллекции, `/app/settings`) лежит в `stepler-container` (контент до 1240, с 1600px — 1320; поля 16/24/32/40) с одинаковыми отступами сверху и снизу: `AdminPage` в `apps/web/src/components/admin-page.tsx`.
- **Один левый край.** Back-ссылка, h1 и вкладки коллекции начинаются у левого края контейнера на каждой странице; блок шапки одинаковый (`grid gap-4`: шапка, затем вкладки), поэтому при переходе между вкладками коллекции и её настройками они не сдвигаются.
- **Вся ширина контейнера на каждой странице** (решение владельца 2026-10-02: колонка 640px в настройках «выглядела странно» рядом с вкладками во всю ширину). Списки, сетки кадров и карточки ссылок занимают контейнер целиком; страницы настроек тоже, но от `lg` каждая секция делится на колонку заголовка (17rem) и панель (остальное), см. 6.8. `AdminFormColumn` удалён.
- Диалоги и центрированные одиночные шаги (вход, подтверждение почты) — вне этого правила.
- **Оболочка admin (решения владельца 2026-10-02, отменяют «без section nav» от 2026-10-01).** Слева от `lg` — sidebar 15rem (цвет страницы, hairline справа): wordmark и кнопка сворачивания сверху, затем «Колекції» и сразу под ней «Акаунт». Только верхний уровень: разделы коллекции — её вкладки, подгруппа их дублировала бы. Текущий раздел — на листе (`--card`, край 1px), `aria-current="page"` на своей странице и `"true"` внутри (коллекция). Сворачивание — в рельс 72px с иконками и tooltip, запоминается в cookie `st_sidebar` (сервер рендерит уже свёрнутым — без прыжка). Ниже `lg` — тот же nav в левом `Sheet` за кнопкой меню. Сверху справа в баре 56px — блок аккаунта без dropdown: аватар, имя над почтой, отдельная «Вийти». Хлебные крошки над h1 страниц коллекции («Колекції › {название}», «› Параметри»). **Одно слово — одно место:** «Акаунт» (имя, тема, язык), «Редагувати колекцію» → «Параметри колекції», «Керувати» (настройки ссылки); «Налаштування» в admin не используется.

## 9. Доступность

**Фокус.** `outline 2px violet (--ring = --link), offset 2px` на всём интерактивном, никогда pencil (контраст 5.98–8.81, раздел 2.2). Кадр в сетке — ring вокруг кадра целиком (outline рисуется в gap сетки; у первой колонки — `outline-offset: -2px`, чтобы не обрезался `overflow: hidden` листа — проверить в реализации). Sticky-шапка и доки не перекрывают фокус (`scroll-padding`). Никогда `outline: none` без замены.

**Клавиатура.**
- Сетка admin: один tab-stop на сетку (roving tabindex); `←→↑↓` — по кадрам (вверх/вниз — на `--cols`); `Home/End` — начало/конец строки, `Ctrl+Home/End` — начало/конец коллекции; `Enter` — открыть просмотр; `Space` или `x` — выбрать; `Shift+стрелка` — расширить выбор; `Ctrl/⌘+A` — выбрать все видимые (по фильтру); `Esc` — снять выбор / выйти из режима; `Delete`/`Backspace` — ConfirmDialog удаления выбранного. Односимвольные сочетания (`x`) работают только когда фокус в сетке (WCAG 2.1.4). `?` — диалог со списком сочетаний; ссылка «Клавіатурні скорочення» в меню «⋯» сетки.
- FrameViewer: `←→` — соседние кадры, `Esc` — закрыть, фокус возвращается на кадр.
- Гость: всё доступно Tab-ом; кнопка «Додати фото» — нативный `<input type="file" multiple accept=…>` за кнопкой (label), без кастомного drag-only; drag-and-drop на desktop — дополнение.
- Timeline — список ссылок.

**Скринридеры.**
- Upload: один регион `aria-live="polite"` для сводки (не для каждого файла); объявления агрегируются не чаще раза в 5 с и на событиях: начало («Завантажуємо 30 кадрів»), каждые ~25% и финал («Додано 27 з 30. 3 не вдалося»); процент каждого файла не объявляется. Остановка всей очереди (offline, квота) — `role="alert"` один раз. У каждого `UploadFrame` доступное имя с состоянием («Кадр 6 з 30, не вдалося: зв’язок перервався. Повторити» — кнопка отдельно).
- Кадры: доступное имя «Кадр 86, фото, 21:10[, нове][, вибрано]»; `aria-pressed` в режиме выбора; изображение внутри `alt=""` (имя на кнопке). `PencilMark` всегда `aria-hidden`.
- Счётчики, диапазоны: «#087–#116» озвучивается как «кадри з 87 по 116» через sr-only текст (моно-строка `aria-hidden`).
- Toast `role="status"`, ошибки `role="alert"` (поведение v4).
- `lang="uk"`/`"en"` на `<html>`, `lang` на переключателе языка.

**Touch.** Цели ≥ 44×44, между соседними ≥ 8 (кроме кадров сетки: кадр ≥ 95px — сам по себе большая цель; gap 1px допустим, т.к. каждый кадр ≥ 44 по обеим осям). Главная кнопка гостя 56, в нижней трети. `touch-action: manipulation`. Long-press выбора всегда имеет альтернативу — кнопку «Вибрати». Свайпы (sheet, viewer) — всегда с кнопкой.

**Контраст.** Все текстовые пары ≥ 4.5, non-text ≥ 3 (2.2). Текст поверх фото — только на `--scrim` (≥ 4.74 в худшем случае). Зум 200% и 400% (reflow 320 CSS px): без горизонтального скролла страницы, кроме осознанных скроллеров (табы, полоса кадров, timeline).

## 11. Продуктовые и data-последствия (не решено молча)

### 11.1 Стабильный номер кадра

C опирается на номер кадра в порядке поступления. Вычислять на клиенте нельзя (зависит от фильтра, страницы и удалений), нужен номер, сохранённый на бэкенде.

- **Хранение.** Варианты: (a) счётчик `nextFrameNo` в строке коллекции, инкремент в той же транзакции, что и создание элемента (`UPDATE … SET next = next + 1 RETURNING`), + `UNIQUE (collection_id, frame_no)`; (b) PostgreSQL sequence на коллекцию — не масштабируется по числу коллекций, не подходит; (c) `ROW_NUMBER()` при чтении — нестабилен при удалении. **По умолчанию (a)** — блокировка строки коллекции на время вставки, при MVP-нагрузке приемлемо; ограничение уникальности в БД, а не в коде.
- **Когда присваивать.** (a) при создании upload session — номера видны сразу («#087» во время загрузки, как в артборде), но отменённые/упавшие загрузки оставляют дыры; (b) при подтверждении завершения — дыры только от удаления, но во время загрузки показывается «1 з 6», а номер появляется по завершении. **По умолчанию (b)**: честнее и проще; артборд в этой части меняется.
- **Параллельные гости.** Два гостя грузят одновременно → номера перемежаются. Диапазон «Ваші кадри #087–#116» верен только если номера подряд. Правило: диапазон показывается только для непрерывной последовательности, иначе «Ваші кадри: 30» и номера на каждом кадре.
- **Дыры после удаления.** (a) честно, как плёнка: номера не переиспользуются и не пересчитываются никогда; (b) перенумеровывать — ломает ссылки «#086» в разговорах admin-а. **По умолчанию (a)**; у admin в подсказке «Номери не змінюються після видалення».
- **Видны ли гостям.** (a) только admin; (b) admin + свои кадры гостя; (c) всем. **По умолчанию (b)**: в общей гостевой галерее — время, без номеров (дыры от удалённых и «#412» у чужих ничего не дают гостю). Тексты (текстовые вклады) получают номера в той же последовательности? По умолчанию **да** — это тоже кадр плёнки; иначе две последовательности.

### 11.2 Время события: съёмка vs загрузка

Timeline по часам и подпись «21:10» осмыслены, только если ясно, какое это время. Гости часто загружают на следующий день — тогда по времени загрузки все кадры лягут в «10:00 наступного дня».

- (a) **Время загрузки** — есть всегда, без обработки; timeline = «коли додано». Честно, но для «плёнки события» хуже.
- (b) **Время съёмки** из EXIF `DateTimeOriginal` (фото) и `creation_time` (видео) извлекается в асинхронной обработке (та же, что делает thumbnails); fallback — время загрузки с пометкой. Проблемы: EXIF без часового пояса (`OffsetTimeOriginal` бывает не всегда) → показывать «как на часах камеры»; мессенджеры и скриншоты EXIF удаляют; неверные часы камеры; документы и тексты времени съёмки не имеют.
- (c) сортировка сетки по номеру (поступление), timeline — по времени съёмки: номера в сетке перестают идти подряд. Нужно выбрать один порядок.
- **Приватность:** EXIF содержит GPS. Оригиналы неизменяемы (правило хранения), значит скачанный оригинал содержит координаты гостя. Это вопрос независимо от timeline: удалять GPS из производных — да; из оригинала при скачивании другими — продуктовое решение.

**По умолчанию для MVP:** (a) время загрузки, timeline подписан «Додано о…», сетка по номеру; при обработке сохранять `capturedAt` (nullable), если это дёшево в выбранном pipeline, чтобы перейти на (b) без миграции данных. Блокирует только `EventTimeline` (PR 11) и подпись времени.

### 11.3 Прочие последствия

- **«Нове» для admin** требует знать, что admin уже видел: `lastSeenAt` на (admin, collection) или «нове = за последние 24 часа». По умолчанию — `lastSeenAt` при открытии коллекции (одно поле); без него отметка «нове» в dashboard не работает.
- **«Ваші кадри» у гостя** требуют владения через guest session (оно уже нужно для `canDeleteOwn`). На другом устройстве/после очистки cookies свои кадры не видны — текст должен это допускать («Кадри, додані з цього пристрою»?).
- **Длительность видео** и **число страниц документа** в подписи кадра — метаданные из обработки (ffprobe и т.п.). Без них кадр видео показывает только ▶; страница документа — необязательно.
- **«86 кадрів · остання о 21:10»** на guest-странице раскрывает активность коллекции — показывать только при `canViewGallery` (и вопрос 12.3).
- **Локальное прев’ю** на экране успеха (`PrintStack`) использует файлы из памяти вкладки; после перезагрузки — thumbnails с бэкенда или «Готується прев’ю». HEIC локально не показывается в большинстве браузеров → плейсхолдер.
- **QR светлый в dark** — сканируемость важнее темы; QR в PNG/SVG всегда тёмный на белом.
- **Номер ссылки/коллекции** не вводим — нумеруются только кадры.

Контраст ring ≥ 5.98 на всех поверхностях (раздел 2.2). Карандаш остаётся для выбора, «нове», активного таба и главной кнопки гостя.
- **12.18, шрифты:** woff2 Geologica и Geist Mono в репозитории с лицензией OFL; Next.js и Storybook используют одни и те же файлы.
